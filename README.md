# ПожЭксперт+

Учебный прототип информационной системы управления проектированием систем пожарной безопасности с ИИ-помощником (курсовой проект).

Заказчик (учебный): ООО «ПожЭксперт+». Все данные в системе — **вымышленные демонстрационные данные** (в интерфейсе стоит метка «Демо-данные»).

## Публикация на GitHub Pages

1. Создайте на GitHub новый репозиторий (например, `pozhexpert`), публичный.
2. Загрузите в него **содержимое** этой папки (`index.html`, `css/`, `js/`, `README.md`, `.nojekyll`). Можно через веб-интерфейс: *Add file → Upload files*, либо командами:
   ```bash
   git init
   git add .
   git commit -m "ПожЭксперт+: учебный прототип"
   git branch -M main
   git remote add origin https://github.com/<логин>/pozhexpert.git
   git push -u origin main
   ```
3. В репозитории откройте *Settings → Pages*, в разделе *Build and deployment* выберите *Source: Deploy from a branch*, ветку `main` и папку `/ (root)`, нажмите *Save*.
4. Через 1–2 минуты сайт будет доступен по адресу `https://<логин>.github.io/pozhexpert/`.

## Архитектура и стек

GitHub Pages размещает только статические файлы и не запускает серверный код. Поэтому базовый стек из п. 8.1 ТЗ (Django + MySQL) заменён на статическое веб-приложение (п. 8 ТЗ допускает иной стек по требованию учебного заведения при сохранении функциональных требований):

| Требование ТЗ | Реализация в прототипе |
|---|---|
| Серверная часть, проверка прав на сервере | Слой бизнес-логики `js/api.js`: все действия проходят через функции с проверкой роли, статусов и зависимостей. Интерфейс только вызывает их; скрытие кнопок проверку не заменяет. |
| База данных MySQL | Таблицы хранятся в `localStorage` браузера (JSON). Структура соответствует схеме БД: users, clients, projects, stages, documents, versions, reviews, remarks, notifications, audit, aiArchive. |
| Каталог `media` для файлов | Файлы хранятся в IndexedDB браузера, в БД — только метаданные и ключ файла. |
| Хеши паролей | Соль + многократное SHA-256, пароль в открытом виде не хранится. |
| ИИ: TF-IDF + косинусное сходство (scikit-learn) | `js/ai.js`: тот же алгоритм на JavaScript (нормализация, стемминг, биграммы, TF-IDF, косинус). Внешние сервисы не вызываются. |
| Резервное копирование | Профиль директора → «Выгрузить резервную копию» (БД + файлы в одном JSON) и «Восстановить из копии». |

**Ограничение такого подхода:** данные хранятся в браузере каждого пользователя отдельно (нет общего сервера). Для демонстрации и проверки преподавателем этого достаточно: все роли проверяются в одном браузере входом под разными учётными записями. Для реальной работы нужен серверный вариант (Django + MySQL), слой `api.js` переносится на сервер без изменения экранов.

## Структура проекта

```
index.html          — точка входа
css/style.css       — стили (палитра и типографика по п. 7.1 ТЗ, светлая и тёмная тема)
js/store.js         — хранилище: localStorage, IndexedDB для файлов, хеширование паролей, сессия
js/seed.js          — демонстрационные данные (помечены isTest)
js/api.js           — бизнес-логика, права доступа, статусы, журнал аудита, уведомления
js/ai.js            — ИИ-помощник: TF-IDF и косинусное сходство
js/ui.js            — общие элементы интерфейса (метки, модальные окна, формы)
js/views-*.js       — экраны
js/app.js           — маршрутизация, каркас страниц, экран входа
```

## Что реализовано

- Вход по почте и паролю, без публичной регистрации; блокировка на 15 минут после 5 неудачных попыток; смена временного пароля при первом входе.
- 7 ролей, меню и главные страницы по ролям, матрица доступа (п. 3.3 ТЗ); закрытые объекты не открываются по прямой ссылке.
- Проекты: поиск, фильтры, сортировка, пагинация; создание (черновик) и запуск; изменение с записью в историю и обязательной причиной, если затронуты начатые этапы.
- Этапы: сроки, исполнитель, проверяющий, трудоёмкость, ожидаемый результат, зависимости; запрет циклических зависимостей; блокировка зависимых этапов до принятия.
- Диалог назначения с загрузкой сотрудников, предупреждением о перегрузке и обязательной причиной при выборе перегруженного.
- Документы и версии: PDF, DOCX, XLSX, DWG, DXF до 25 МБ; запрет исполняемых файлов; новая версия не перезаписывает старую; просмотр PDF в браузере.
- Поэтапная проверка: передача на проверку, принятие, возврат с обязательным замечанием, повторная проверка замечаний («Принять исправление» / «Не исправлено»), отмена приёмки ГИПом.
- Замечания: фильтры, карточка с историей статусов, перепиской и связанными версиями; статус «Неактуально» с обязательным объяснением; внешние замечания согласующей стороны.
- Клиенты: справочник, предупреждение о дубликатах, архивирование (клиента с проектами удалить нельзя).
- Сотрудники: создание с временным паролем, изменение, смена роли, сброс доступа, блокировка и деактивация с подтверждением.
- Уведомления, журнал аудита, отчёты (сводка, качество, загрузка, календарь сроков) с выгрузкой в CSV.
- ИИ-помощник: до 5 похожих записей выше порога, причина сходства, способ устранения, «Использовать как черновик», «Полезно / Не полезно», честное сообщение при отсутствии совпадений; учитываются только доступные пользователю записи.
- Архив ИИ: кандидаты из закрытых замечаний, проверка специалистом, включение и исключение, настройка порога релевантности директором.
- Светлая и тёмная тема, адаптивная вёрстка.

## Ограничения прототипа

- Данные хранятся в браузере; при очистке данных сайта они удаляются (восстановление — из резервной копии или сбросом демо-данных в профиле).
- Просмотр DWG/DXF в браузере не реализован: файлы хранятся и скачиваются.
- Для демонстрационных версий документов реальные файлы не загружались: при открытии формируется файл-заглушка.
- ИИ-помощник ищет похожие замечания и не заменяет экспертизу; архив ИИ состоит из вручную подготовленных демонстрационных примеров.
